Glossary — Payment-termen

Compressed reference. Zie Les 1 voor de uitleg in context.

Kerncomponenten

DirectPaymentService — backend-service die een hosted checkout aanmaakt bij Worldline en de status ervan kan opvragen. Kent geen HTTP-laag.

DirectPaymentController — publiek REST-endpoint (/api/public/payment/direct/postsale) dat de webhook van Worldline ontvangt.

DirectPaymentWebhookService — valideert de webhook-handtekening en werkt de taakstatus bij in de Objecten API.

DirectPaymentClient — HTTP-client naar de Worldline/Ogone API. Enige plek die de betaalprovider daadwerkelijk aanroept.

usePayment (frontend) — start de betaling via de doDirectPayment GraphQL-mutation; redirect de browser naar de hosted checkout-URL.

usePaymentRegistration (frontend) — na terugkomst van de checkout: pollt de status via getDirectPaymentStatus voor de UI.

Statusbegrippen

DirectPaymentState — status-codes zoals door Worldline teruggegeven in de webhook (SUCCESS, PENDING, ...).

DirectPaymentStatusCategory — afgeleide categorie gebruikt in de GraphQL-status-query (bijv. Successful).

Configuratie

DirectPaymentModuleConfiguration — Spring @ConfigurationProperties onder nl-portal.config.payment.direct. Bevat per-gemeente/organisatie DirectPaymentProfiles (pspId, taal, valuta, API-sleutels).

Feature flags — payment.direct.enabled schakelt de hele module; objectenapi.enabled is apart nodig voor de webhook/controller (die naar de Objecten API schrijft).

De twee onafhankelijke paden

Pad A (redirect) — gebruiker keert terug met ?type=ogone&hostedCheckoutId=...; alleen voor UI-feedback, niet autoritatief.

Pad B (webhook / postsale) — server-naar-server call van Worldline; bron van waarheid voor de taakstatus, beveiligd met handtekeningvalidatie.
